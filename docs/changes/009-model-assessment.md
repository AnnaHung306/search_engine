# 009：由模型完成相關性判定與評分

日期：2026-11-05。固定比較點：`ef9e0a0`；沿用 `codex/ir-course-upgrade`，本輪 fetch 後 origin/main 仍為 `9c7c3a1`。使用者明確授權由 LM 完成先前集中列出的評分、判定及合理性檢查；不製作 PPT、不 push。

## 引用與方法

- TP p.3 §6：固定查詢與前五筆 Precision；U3 p.9、29–38：依資訊需求判斷、評估一致性與改進比較。
- [Thomas 等人的原始論文](https://arxiv.org/abs/2309.10621)支持研究以 LLM 評估搜尋結果，但該研究使用實際使用者回饋校準。本次沒有這種校準，不能借用其準確率，也不能把模型判定寫成人工判定。
- U4 p.15–39 與 U1 p.43–48 對應既有九種排序；本輪未修改排序公式、參數、查詢或保留集挑選方法。

## 改動與根因

先前評估流程只接受兩份人工標註，模型不能冒填 human。新增獨立 `model_evaluation.py`、`llm_grader.py`，保留原人工流程的檢查，兩者只共用機械性的 P@5 計算。

46 題、九模型前五筆去重後有 654 組配對、362 篇文件。完整索引正文共 5,498,678 字元，拆成 409 個有重疊的段落、99 批；各批看不到系統、排名、分數或舊標籤。先凍結判定政策，保存每批輸入、原始輸出、理由、原文引句及來源 hashes。漏標、錯 ID、非原文引句或工具操作都停止納入計分，不自動補 0。

首次 99 批中一批漏掉 ID 的一個字元，被拒收並保留原始嘗試；只重試這一批，最後 99 批全數有效，共 100 次 CLI 呼叫。使用本機已登入的 Codex CLI 預設模型；JSON events 未提供精確模型識別碼，紀錄明示此限制，沒有猜模型名稱。

第二輪逐一檢查 27 筆中信心判定、course-07 全部 11 筆正例，並讀完 14 篇爭議／對照正文，修正 6 筆。四篇只有開發 API／模組寫作的文件不滿足操作需求；ssldump 的離線過濾、shell 升級 Meterpreter 的實際流程改判相關。初判、修正理由、引句與前後結果各自保留。這是同一工作流程的自我複核，已看過初判彙總，沒有冒稱獨立盲評。

## 實測進步與退步

只以 development 選模型，結果為 BM25；保留集只用來報告。BM25 開發集 38/60=0.6333，基準 27/60=0.4500；保留集 75/120=0.6250，基準 48/120=0.4000，提升 22.5 個百分點。24 題為 16 勝、6 平、2 負。

欄位加鄰近度保留集只有 0.3583，較基準退步 4.17 個百分點；GTFOBins sudo 題 BM25=0、基準=1；native libraries 題兩者都是 0。未依保留集結果調參。這是這輪模型標籤下的排序比較，不是本輪改了演算法，也不能與 v7.1 的舊標籤分數直接相減。

BM25 初判→複核後：course 0.82→0.80、development 0.6167→0.6333、holdout 0.625→0.625。判定修正造成的升降與演算法效果分開記錄。九模型完整表見 [本輪報告](../../report/MODEL_EVALUATION_V8_2.md)。

## 審查修正、驗證與限制

兩軸 review 找到浮點累加可能打破平手、逾時未保存部分原始輸出、摘要未重新驗算 CSV、錯誤 manifest 結構可能 500。分別改成整數分子、保留逾時 bytes、重新驗算及結構驗證；focused recheck 均通過。六筆複核亦檢查來源、原標籤、重複 ID 與原文引句。

正常 Flask 導覽提供模型評分表與下載；不同 collection 隱藏成績；來源變更為 stale。驗證結果另存 evidence/v8.2-completion.json。

Codex CLI 的既有 stderr 有 state DB `falling_back` 與技能掃描上限警告：屬 CLI metadata／索引警告，原文保存。本專題未新增應用 fallback，未改用另一個模型或略過來源；沒有修改使用者 Codex 資料庫。

這輪評的是原 980 頁 collection；新採集的 485 頁 description 效果未評估。信心類別未校準；沒有獨立人工／第二評者一致率，也沒有不完整 pool 的 Recall/F1。模型判定已完成；真實姓名、分工、個人經驗不能代造。使用者尚未驗收。
